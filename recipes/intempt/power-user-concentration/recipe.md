# Power user concentration

Slash command: /power-user-concentration

## Step 1: Chart activity by user percentile

Create an Insights report called "Power-User Concentration".
Series A: Event "Session start" (or use the User.Total events computed attribute directly, which is system-maintained), aggregation: Count by user
Series B: Computed: rank users by Series A descending; for each percentile bucket (top 1%, top 5%, top 10%, top 25%, top 50%, bottom 50%), sum events in bucket and divide by total events × 100, unit: %, label: "Share of Total Events"
Time range: Last 30 days
Breakdown: By Plan (saas) or by User.Lifetime value bucket (ecommerce)
Compare: Previous period (prior 30 days)
Chart type: Pareto bar chart: bars showing share of total events per user-percentile bucket, with cumulative line overlay
Annotations:
- Flag the share of total events generated by the top 1% of users: values >25% indicate heavy-tail concentration.
- Flag the share of total events from the bottom 50%: values <10% indicate the long tail isn't engaged.
- Highlight whether concentration is increasing or decreasing vs. previous period.
- For ecommerce mode: substitute "events" with "revenue": sum Placed order.total_price per user, then run the same percentile decomposition.
SaaS products want lower concentration (broad activation); ecommerce often has natural high concentration (loyal whales) but tracking the change matters more than the absolute level.
Taxonomy notes:
- Users.Total events is a system-computed attribute (real, on the Users object). Use it directly for the per-user totals.
- For revenue-side concentration, sum Placed order.total_price grouped by customer_id.
